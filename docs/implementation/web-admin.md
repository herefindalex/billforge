## Getting started

1. It's going to take Go 1.27, CGO, Node.js and pnpm. Copy `.env.example` to `.env`, and set `BILLFORGE_ADMIN_USERNAME` to `BILLFORGE_ADMIN_PASSWORD` with 12 to 72 bytes; Limiting the read permissions of `.env`. Process environment variables can be modified, and the process environment takes precedence over the file.
2. Running in the root directory of projects:

   ```sh
   pnpm --dir web/admin install --frozen-lockfile
   pnpm --dir web/admin build
   go run ./cmd/lab admin ./billforge-data/commerce.db ./billforge-data/provider.db 127.0.0.1:8080
   ```

3. Open the `http://127.0.0.1:8080/admin/` account and log in to `http://127.0.0.1:8080/admin/`. Stop with Ctrl+C. Data is stored in two specified SQLite files; The server will not be deleted.

The selected `BILLFORGE_ADMIN_CAPABILITIES` is a list of comma separation capabilities that must contain `read`; When not set up, give full control of the machine. After the change, the session was disabled. Restart the command that has not yet been executed according to the new capability check: to determine that the not yet executed command is `failed/PERMISSION_REVOKED`, and that the payment/withdrawal that has been sent is still validated with the original operation, maintaining the `waiting_verification` or completing the result. the obligation to withhold the recovery of the batch commenced and the operation which cannot be proved to have been effective without safety; The latter shows `PERMISSION_REVOKED_REVIEW` in the command details and stops the invalid rounds. "Check existing receipt" only looks at the original provider key and the recorded receipt, which may update the native verification results but does not send new provider operations; If the evidence is later examined, the original command can be directly completed. If there is still no evidence, it is necessary to restart the recovery capability and continue the restart.

If you want to specify another file, use `go run ./cmd/lab admin --env-file /path/to/admin.env commerce.db provider.db 127.0.0.1:8080`. The front-end assets are embedded in a binary file with `go build -tags admin_ui -o /tmp/billforge-admin ./cmd/lab`; The first thing to do is to run the front end build. When the development version is not tagged, read assets from `cmd/lab/adminassets/dist`. The two database paths must be different and the management service only accepts explicit loopback IP.

## Operating model

- Access resources, operations and experiment controls from the left-hand menu after logging in. The list of general resources can be sorted by the fields allowed by the resource; This includes the `created_at` price migration, subscription, credit, withdrawal, account migration and reconciliation operation available in UTC. `created_from` (included) and `created_before` (excluded) are entered in RFC 3339. The URLs for the screening conditions, highlights and locations of the returning previous pages are stored. The optical character binds resources and filters, moving forward according to the data order; Data added across pages does not represent the same full-domain snapshot. The command details can be found at `/admin/commands`; `/admin/jobs` can find bulk work according to the order of creation, see the number of completed and processed projects, and `/admin/jobs/:id` displays the results of each project.
- The customer list `/admin/customers` uses the customer ID lighting; Customer details `/admin/customers/:id` Merges subscriptions, offers, bills, Credit with old accounts and can pre-fill new offers. The subscription list `/admin/subscriptions` and the detailed `/admin/subscriptions/:id` show the actual price, seats, billing period, entitlement sources, reasons for the renewal blocks and future arrangements; The list of offers can be accessed by `/admin/quotes`. The data associated with each category of customers shows the most recent 100 posts, and when more is indicated, the interruption; The `/admin/data/customers` path can still be read with the original `/admin/data/Customers` in bold.
- Financial operations are previewed and then commands are submitted. preview binding operators, targets, source revisions, business clock revisions and expiration; Expiration or change of source should be reviewed. The same idempotency key with the same payload should be returned to the original command; The same key refuses to payload.
- The API first stays the command and then runs the domain action. the transaction of the command receipt and the business effect where available; The unknown results of the external fake provider retained `waiting_verification`, which was verified after the original operation. No new payment or refund obligations are created due to the delay of the webpage. Service restart will scan and restore commands.
- Batch work C13, C30, C32, C44, C45 Fixed preview members, submitted per item, sustained success/conflict/wait/short results, unfinished follow-up after restart. Workers lease using wall clock and generation fencing; The old worker can't rewrite the results of the takeover.
- `/admin/lab/controls` can set up a persistent business clock, a payment or refund fake provider decision, and a one-time specified failure. When `lab.control` is enabled, the page also displays receipts, refunds, set decision numbers, and default notes from independent provider databases; `/admin/lab/provider-captures`, `/admin/lab/provider-refunds` provides a status screen and a highlight page. Provider decisions and control receipt transactions; The clock is still active after the restart. Business and provider data, observed separately, and experimental controls do not represent actual payment service behaviour.

- The browser's management API reads the wait limit of 10 seconds and other requests of 20 seconds. The delay only indicates that the browser has not received a definite response; The command page retains the original request key, and after verification, another one can be started. An overview and a list of the data that were last successfully read will show the update of the failure alerts and the time of the original observations if they are retained; After successfully re-reading, the alert disappears.

## Login and permissions

Sign in to the server side session with CSRF verification. The session has a 30-minute suspension and a total duration of 8 hours. Error passwords and unknown accounts return the same message, failing to verify at a limited speed. The C01 and C49 actions are mapped to each API. The C01 created contract offerings and the C02 accepted contract offerings required simultaneously `subscription.manage` and `contract.manage`, with the general scheme offering only the former. `.env` is currently a single management account defined by `.env`, with no multiple user permissions to edit images. The password must not be entered in `VITE_` variables or front-end assets.

## Database upgrades and restorations

`admin` will be operated by `InitAdmin`. Both admin schemas v1 and v8 are upgraded in a single transaction, including preview clock revision, indexing of invoice sources, and command/verification request ID fields; Upgrading failures will roll back, and re-running can remain idempotent. Before upgrading, please backup two persistent SQLite files and try running them in the offline copy. Business time at the time of submission is retained for the running command; After that, the clock moves and the old preview is disabled.

If the UI shows the command waiting, go to the command details to see the original id and status, and then use the same command's restore input. Do not change the idempotency key to rebuild the obligation. Verify the proof of original operation of a fake provider when there is an uncertain response to a payment or refund. Batch work looks at each result by job ID, and successful items will not be used again.
