# 交互式菜单 CLI

[English](interactive-cli.md) | [繁體中文](interactive-cli.zh-TW.md) | **简体中文**


日期：2026-09-26。此接口操作 Billforge **已实作**的 S01–S12、P01 与 P03 本机切片；它使用两个持久化 SQLite 文件，其中 Commerce 与 fake provider 各有独立状态。没有真实支付连接。

## 启动

```sh
go run ./cmd/lab
# 或直接指定要继续使用的数据库
go run ./cmd/lab menu ./billforge-data/commerce.db ./billforge-data/provider.db
```

不带路径时，程序会询问两个文件位置，按 Enter 使用 `./billforge-data/commerce.db` 与 `./billforge-data/provider.db`。同一路径再次打开可继续操作原数据。主菜单按 `0` 离开；子菜单按 `0` 返回。对象可输入清单编号或完整 ID，选择对象时留空可返回。

| 菜单 | 可做的事 |
| --- | --- |
| 查找目前状态 | 查看报价、订阅、帐期、发票应收／净已付／未付、付款、更正、credit、credit 应用、退款及待处理 outbox；按对象查详情，或单独查看 fake provider 结果。 |
| 报价与新购 | 创建 Basic、Pro 或已发布方案／cohort 报价，接受报价并创建初始付款操作。 |
| 付款 | 创建部分付款、重试确定失败的付款、送出下一笔付款、以原操作查证 UNKNOWN、设置 fake provider 结果。 |
| 续约与权益 | 运行到期续约、根据已提交的帐务事实重建权益。 |
| 发票更正与 credit | 对已定稿发票过帐减额、把有来源的 credit 应用于后续续约发票。 |
| 退款 | 保留退款额度、送出、查证 UNKNOWN、设置 fake provider 结果。 |
| 设置仿真时间 | 输入 RFC3339 UTC 时间，例如 `2026-10-01T00:00:00Z`，或输入 `real` 恢复系统时间。 |
| 订阅调度与取消 | 以目前 revision 排下期 Basic／Pro 变更、期末取消，或在取消生效前恢复。 |
| 价格版本与 cohort 迁移 | 发布 Pro 或配置式计量价格、注册 meter、指定 cohort，并预览／管理既有订阅迁移。 |
| 用量与关帐 | 依订阅 meter 记录事件、撤销事件、关帐、晚到重算及负差额 CreditNote。 |
| 企业合约与 Net30 | 发布合约、报价、接受并先开通服务，处理到期收款。 |
| 对帐、修复与人工决议 | 保存差异证据，指定安全修复、查原付款操作，或记录人工决议。 |
| 帐户边界与灰度迁移 | 创建来源 ID 映射、唯读 shadow 比较、历史来源回填、读取／写入切换及停止操作。 |

金额输入为**整数最小货币单位**：USD 20.00 请输入 `2000`。请求键是业务操作的身分；同一操作重试时必须输入**相同**键。付款或退款显示 UNKNOWN／仿真崩溃时，应用菜单中的「依原操作查证」，不要以新请求键再送出。`lost_response` 与 `crash_after_provider` 可在送出操作时选择。

## 一条可手动走通的路径

1. 在「设置仿真时间」输入 `2026-09-01T00:00:00Z`。
2. 在「报价与新购」创建 Basic 报价并接受，记下请求键。
3. 在「付款」送出初始付款；在「续约与权益」重建权益。
4. 在「发票更正与 credit」将 $20 发票减额 `400`，产生 $4 credit。
5. 在「退款」保留并送出 `200`；在「设置仿真时间」移到 `2026-10-01T00:00:00Z`，然后运行续约。
6. 将剩余 `200` credit 用于续约发票；创建 `1800` 的新付款并送出，再重建权益。
7. 在「查找目前状态」确认初期应收 `1600`、续约 credit 应用 `200`、退款成功 `200`，grant 可用额度 `0`。

仿真时间只存在当前 CLI 工作阶段，重新打开后回到系统时间；已写入的帐务事实持久保存。Commerce 总览在单一唯读交易中读取；fake provider 使用另一个数据库，画面会分开显示，两边不是同一个跨数据库快照。这个小型 lab 的状态查找未分页，不作为正式营运接口。
