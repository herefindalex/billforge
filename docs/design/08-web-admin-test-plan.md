## 1. Evidence with a common matrix

Each running record keeps a source revision or workspace hash, schema version, environment/clock, data seed, command, results, and trace of failure. The test accounts and data are synthesized. It is not possible to judge success by HTTP 200 alone, but by verifying the financial facts of the database, command receipt, provider fake records and UI status.

**C01 C49 Each command** must have: legal payload, field/range errors, absence of session, lack of capability, cross actor preview, same key with payload, same key with different payload, same object replay, UI success/error presentation. The commands that require a preview are expiry, source change, other commands have been claimed, revalidation within the transaction; Class N still needs to verify its independent business source guard. The application form cannot be abbreviated by default; Any N/A needs a corresponding method and reasoning.

All of the GET lists are alternate: missing/maximum limit, unknown filter, cursor and filter incompatibility, stable ordering, blank results, cancellation, de-sensitivity, schema type, cross-page meanings when data is inserted. When the ID does not exist or for different resource types, return it to 404/422, without triggering input.

## 3. UI pathways and automation strategies

Playwright's test path covers the entire page of the engineering contract. The shared component is used to check the exact amount, status mapping, form validation, keyboard/focus with the Vitest/React Testing Library. Financial truth is still determined by Go transaction tests and E2E with an actual database. The web request mock is only used for loading/error component testing and cannot replace a payment/refund/return scenario.

In parallel, use a channel/barrier or controllable test hook to arrange interleaving without sleep guessing. Provider failure is controlled by the existing model of the fake provider with a specific test hook, not outside testing. Log in to the fixture using the temporary `.env` and the formal session path; You can't bypass the production bundle.

For each command in the A30 audit, pre-fill the following: action ID, UI route, handler, domain helper, source guards, permission, preview policy, receipt policy, HTTP tests, browser scenarios, proof of running. These fields remain blank and unfinished without evidence and cannot be determined by the presence of documents.

## 4. Known limitations and non-declarations

This plan does not measure real provider, cross-regional consistency or public deployment security. One instinctive browser smoke cannot demonstrate the completion of 49 functions; Similarly, a command table has records that do not represent transactions with business facts. Each invariant will need a financial source and a disruption test to make a decision.
